**Notes:**
```
The format is based on JSON but may include base64-encoded binary content. Encoding is declared as "binary" to accommodate line lengths and characters beyond the 7-bit ASCII range.
```

**Security Considerations:**
```
This media type does not contain active or executable code. Pyon files consist of JSON-compatible structures with additional metadata used to reconstruct Python objects. No user-defined methods (e.g., __init__, from_json) are executed.

Certain types (e.g., datetime, decimal, numpy, pandas, Enum, defaultdict, namedtuple, File) rely on constructors during restoration. These constructors are invoked in a controlled and deterministic way, without arbitrary code execution. Full details are documented in SECURITY.md in the public repository.

Decoding `.pyon` files generated by trusted sources is safe. Files from untrusted sources should be treated with caution and may require validation. The format itself does not provide confidentiality, integrity checks, access control, or encryption. These protections must be applied externally.

As a JSON-derived format, risks such as high memory/CPU use on deeply nested documents also apply. These limitations are discussed in SECURITY.md.
```

**Interoperability Considerations:**
```
Pyon files are JSON-syntax but not fully interoperable with standard JSON parsers. They include metadata (e.g., type tags) required for reconstruction. Generic JSON tools may parse the structure but cannot restore original objects without Pyon-specific logic.

Compatibility is best ensured by using official libraries. See README.md in the repository for specification details.
```

**Applications That Use This Media Type:**
```
The Pyon library (https://github.com/eonflux-ai/pyon) is the reference implementation. It is used to serialize and deserialize Python objects, including complex types such as NumPy arrays, pandas DataFrames/Series, and custom classes. Intended use cases include machine learning pipelines, configuration management, and object persistence.
```
